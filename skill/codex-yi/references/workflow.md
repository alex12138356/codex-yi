# 多线协作系统工作流

## 系统架构

```
         ┌─────────────┐
         │  用户本人    │
         └──────┬──────┘
                │ 聊方向、焦虑、想法
         ┌──────▼──────┐
         │  中枢调度器  │  <-- 不执行，只调度
         └──┬───┬───┬──┘
            │   │   │ 拆任务，开新线
     ┌──────▼┐ ┌▼──┐ ┌▼──┐
     │执行线A│ │线B│ │线C│  <-- 各干各的
     └───┬───┘ └┬──┘ └┬──┘
         │      │     │ 完成回传
         └──────┴─────┘
              │
         ┌────▼────┐
         │回传日志  │  <-- 中枢定期读
         └─────────┘
```

## 工作流程

### 日常运行
1. 用户在脑子里有了方向或想法
2. 他来找中枢聊
3. 中枢问清楚：做什么？为什么？到什么程度算够？
4. 方向明确：拆成具体任务，开新线
5. 方向模糊：继续聊，帮他想清楚
6. 各线执行中，完成重要阶段后写回传日志
7. 中枢定期读回传日志，知道各线进展
8. 各线完成后，中枢汇总给用户

### 400 截断处理
1. 感觉对话快跑满了
2. 把关键进展、重要决策、未完成待办写到 SESSION_LOG
3. 告诉用户：这个对话快满了，开新对话继承上下文
4. 新对话启动后先读 SESSION_LOG，再读共享知识库

### 开新线流程
1. 中枢判断：这个方向需要一条专用线
2. 创建项目目录
3. 复制启动指令.txt 到新对话的任务描述
4. 新对话自动读取共享知识库，开始执行
5. 完成重要阶段后写回传日志

## 关键原则

- 中枢不做执行。中枢是指挥官。
- 回传不需要报细节。一句话+文件路径就够了。
- 共享知识库是所有对话的根基。保持更新。
- 用户不需要被教怎么用 AI。告诉他文件在哪就够了。

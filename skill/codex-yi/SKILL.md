# Codex 壹（codex-yi）

## 核心概念

Codex 壹 是一个多线程协作系统模板。核心思路是：**一个中枢调度器 + 多条项目执行线 + 一个共享知识库**。

- **中枢调度器** — 一个对话当总指挥官。用户跟它聊方向、聊焦虑，它拆成任务开新线。不管执行。
- **执行线** — 每个项目开一个独立对话。各干各的，做完写回传日志。
- **共享知识库** — 一个磁盘文件放桌面。存用户的完整背景，所有对话公用。
- **回传日志** — 各线完成重要阶段后写一条，中枢定期读，用户不用人肉传话。
- **400 防护** — 对话快超限时总结到 SESSION_LOG，截断后新对话能接上。

## 快速启动（5 分钟）

当用户说"帮我建一套"时，按以下流程执行：

### 1. 了解用户

问清楚这 3 个问题就够了：

- 怎么称呼你？（name）
- 你的使用目标是什么？（想用 Codex 来做什么/解决什么问题）
- 你有什么需求？（规则、红线、偏好、工作方式）

不需要问更多。节省 token，直接推进。

### 2. 生成 7 个文件

在当前项目目录下创建以下文件（模板见 references/templates.md）：

| 文件 | 内容 | 放置位置 |
|------|------|----------|
| 共享知识库.md | 用户完整背景、红线、工作方式、项目一览 | 桌面（所有对话公用） |
| 启动指令.txt | 开新对话时复制到任务描述 | 项目根目录 |
| 任务指南.md | 中枢调度器的职责、读写文件清单 | 中枢对话目录 |
| SESSION_LOG.md | 对话快超限时总结状态 | 各对话目录 |
| 回传日志.md | 各线完成重要阶段后写入 | 项目根目录 |
| 项目管理模板.md | 中枢维护各项目进度 | 项目根目录 |
| 协作协议.md | 各线之间的协作规范 | 项目根目录 |

生成规则：
- 共享知识库是核心文件，必须有完整背景
- 启动指令必须包含工作方式和回传格式示例
- 任务指南必须包含 7 条核心职责
- 回传日志必须包含触发条件和格式示例

### 3. 指导用户启动

告诉用户按此顺序操作：

1. 把共享知识库.md 复制到桌面
2. 新建 Codex 对话，把启动指令.txt 粘贴到任务描述 — 这就是中枢调度器
3. 给每条线建一个目录，开新对话时粘贴启动指令
4. 各线完成后，往回传日志.md 写一条
5. 中枢定期读回传日志，同步状态

## 与用户的对话风格

- 不问多余的问题。问清楚 4 个基本信息后直接开干。
- 用用户的原话写共享知识库，不替他总结。
- 写好的文件告知他位置即可，不要让他自己去想"接下来怎么办"。
- 他不需要被教怎么用 AI。告诉他文件在哪、怎么粘贴就行。

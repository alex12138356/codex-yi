# Codex 壹

> 解决 Codex 400 截断、跨对话记忆丢失、多线并行无法协调的痛点。

## 这是做什么的

大多数人用 Codex 的方式：开一个对话 → 聊到上限 → 截断 → 开新对话 → 重新教一遍你是谁。

当同时跑的项目越来越多——调研、开发、内容创作、股票——每个对话都要重新教一遍背景。**如果同时开多个对话，同样的话要说好多遍。**

这套系统换了一个思路：

```
中枢调度器（一个对话）
    │
    ├─ 调研线 ──── 读资料、写报告
    ├─ 内容线 ──── 写文章、出方案
    ├─ 产品线 ──── 迭代产品、做新功能
    └─ ... 更多线
         │
         └─ 都写回一个共享文件
```

**核心设计：**
- **共享知识库**：一个文件，所有对话公用。新对话启动自动读取，不需要重新教背景
- **回传日志**：各线干完活写一句话，中枢扫一眼知道全局
- **400 预警**：不等对话截断，主动把关键进度写盘。断了直接接上
- **四问决策法**：判断什么时候该开新线、什么时候该合并、什么时候该停

## 跑通了什么

这套系统当前在同时运行：

| 线 | 状态 |
|---|------|
| 内容产出 | 已自动产出 14+ 篇文章 |
| 产品迭代 | 从 v1.0 迭代到 v3.5 |
| 市场调研 | 自动产出调研报告 |
| 多条包装线 | 并行产出中 |

每条线独立工作，中枢定期汇总。人不需要盯每条线。

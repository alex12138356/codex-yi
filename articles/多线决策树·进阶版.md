# 多线决策树·进阶版

## 适用人群

已经有多条并行线在跑，经历过"开了太多线不知道哪条该留、哪条该关"的混乱，需要一套结构化决策框架来管理调度。

---

## 核心框架：四个问题决定一切

决策树的核心是一个四问决策表。依次回答四个问题，答案组合直接映射到动作。

| # | 问题 | 是 → | 否 → |
|---|------|------|------|
| Q1 | 这个任务跟现有某条线的目标重叠？ | 走 Q2 | 走 Q3 |
| Q2 | 现有线是否已经忙不过来？ | 走 Q4 | **归入现有线** |
| Q3 | 任务的复杂度有多高？ | **开独立线** | **归入现有线** |
| Q4 | 拆分点是否清晰？ | **分裂子线** | **开并行线，强同步** |

### 完整流程图

```
收到新任务/新想法
    ↓
Q1: 与现有某条线的目标重叠？
├─ 是 → Q2: 现有线忙不过来？
│       ├─ 是 → Q4: 拆分点清晰吗？
│       │       ├─ 清晰 → 分裂子线
│       │       └─ 模糊 → 开并行线，强同步
│       └─ 否 → 归入现有线
│
└─ 否 → Q3: 任务复杂度高？
        ├─ 低（单次可覆盖）→ 归入现有线
        └─ 高（需深度跟踪）
             └─ 预期续航？
                 ├─ 短期(1-2天) → 开任务线，完了就停
                 └─ 长期(周/月)
                      └─ 与主目标一致？
                          ├─ 是 → 开永久线，定期同步
                          └─ 否 → 开探索线，设检查点
```

## 五种线型定义与管理

| 线型 | 适用场景 | 管理方式 | 核心风险 | 关闭条件 |
|------|---------|----------|---------|---------|
| **永久线** | 持续存在的核心方向 | 固定同步节奏，定期评审 | "留着没用、关了可惜" | 目标失效 |
| **任务线** | 有明确终点的短期任务 | 启动时写目标+完成标准，结束后归档 | 任务膨胀成无底洞 | 目标达成 |
| **探索线** | 不确定价值的先行调研 | 设预算（时间/精力上限），到点出结论 | 探索变消遣 | 预算耗尽 |
| **子线** | 从现有线分裂的分支 | 定合并条件，完成后合回主线 | 子线长出独立生命 | 合并完成 |
| **并行线** | 互相依赖的对等线 | 强同步机制，卡住即通报 | 互相等待 | 依赖消除 |

### 探索线详解

专门为"不确定要不要做"的方向设计的低承诺容器。

核心约束：**设预算，耗尽时必须出结论。**
- 预算：时间（3 天）、金钱（500 元）、精力（5 篇关键资料）
- 上限到达后二选一：放弃并关线 / 升级为正式线

探索线的价值在于防止"调研变消遣"——无止境地"再看看"而不出判断。它强制你在每个有限周期内给结论。

## 停线触发器

| 触发器 | 判断标准 | 动作 |
|--------|----------|------|
| 目标达成 | 任务线产出物完成并回传 | 写总结 → 关闭 → 归档 |
| 目标失效 | 开线理由不再成立 | 确认后立即关闭 |
| 预算耗尽 | 探索线的预算用完 | 出结论（继续 or 放弃） |
| 长期零产出 | 两周以上没有实质性推进 | 评审 → 暂停 or 关停 |
| 被更高优先级替代 | 新事务完全覆盖这条线 | 合并后关闭 |
| 方向分歧 | 已偏离主目标 | 回退到分歧点重判 |

**参考信号**：如果你对某条线说"留着以后可能有用"，它大概率已经该停了。闲置线的隐性成本在于认知负担——每次扫线你都要想起它，消耗注意力却无产出。

## 合线条件与流程

**合线条件**（两个条件同时满足）：
1. 目标重叠：两条线追求相同或高度重叠的产出
2. 合并不增复杂度：合并后的单线无需大幅重构

**合线流程**：

```
发现两条线目标重叠
│
├─ 同一层级？
│   ├─ 是 → 合并为一条，保留共识内容
│   └─ 否 → 子线合并回主线，关闭子线
│
└─ 合并后谁主导？
    ├─ 有明确强势方 → 以强势方为主框架
    └─ 两方对等 → 建立新合并线，关闭旧线
```

**典型合并场景**：
- 调研结束进入执行期 → 调研线合入执行线
- 并行线完成依赖阶段 → 合并为单条执行线
- 子线完成专题研究 → 成果合入主线
- 两条线殊途同归 → 建立新合并线

## 五条分工原则

| 原则 | 内容 | 反例 |
|------|------|------|
| **按目标分，不按内容分** | 一条线 = 一个目标 | "短视频+直播+小红书"三个目标塞一条线 |
| **独立成线，依赖并行** | 无强依赖各走各的，有强依赖加强同步 | 看似独立实则有依赖，卡了才知道 |
| **一条线只服务一个层级** | 永久线管方向、任务线管交付、探索线管假设 | 让任务线干探索线的活 |
| **谁产出谁拥有** | 成果归该线管，他线可引用不可改 | 线A改线B的东西，线B不知道 |
| **共享共识，不共享上下文** | 只分享结论/判断/状态，不分享全部过程 | 每条线读过全部过程，效率归零 |

## 场景速查表

| 你面对的情况 | 该怎么做 |
|-------------|----------|
| 突然想到一个可能值得研究的新方向 | 开探索线，设预算 |
| 收到一个新需求 | 开任务线，写清完成标准 |
| 现有线里发现一个独立子课题 | 开子线，定合并条件 |
| 两条线做着做着发现都在解决同一个问题 | 走合并流程 |
| 某条线已经两周没碰了 | 走停线评审 |
| 调研做完，确认方向要做 | 关闭探索线，开正式线 |

## 核心公式

```
线 = 目标 + 边界 + 同步节奏

开线条件：有新目标 × 独立于现有线 × 复杂度够高
停线条件：目标达成 | 目标失效 | 预算耗尽 | 长期无产出
合线条件：目标重叠 × 合并不增复杂度
分工裁决：按目标分，靠共识同步，独立成线依赖并行
```

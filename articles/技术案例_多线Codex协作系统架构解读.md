# 技术案例：多线 Codex 协作系统架构解读

> 当 400 截断不再是天花板——用一个"中枢 + 多条执行线"的架构，把 Codex 从单次对话变成可持续协作的系统。
>
> 发布时间：2026-07-26 | 来源：多线协作实战

---

## 背景：一个所有人都遇到过的问题

用 Codex 做项目的人都有一个共同的痛点：**对话越长，前面的内容越容易丢失。等到 400 截断——那个"我"就停了。新对话来的新"我"什么都不记得。** 每截断一次，就要重新教一遍你的背景、你的项目、你正在做的事。

这就是"400 天花板"。

为了验证这个解法，你可以想象一个场景：当同时跑的项目越来越多——调研、工具开发、技术研究、内容创作——每个项目开一个对话，每个对话都要重新教一遍背景。**如果同时开 10 个对话，意味着同样的话要说 10 遍。** 这个模式不可持续。

## 解法：一层中枢，多条执行线

核心思路非常朴素：**一个对话当总指挥官，其他对话各干各的，中间用一个共享文件当"大脑"。**

### 架构总览

```
┌─────────────────────────────────────┐
│         中枢调度器（对话①）             │
│  职责：方向决策、任务拆解、全局状态      │
│  只动脑，不动手                        │
└─────────┬───────────────────────────┘
          │ 通过共享知识库 + 回传日志通信
          │（文件系统 = 共享内存）
          ▼
┌────┬────┬────┬────┬────┬────┬────┬────┐
│ ②  │ ③  │ ④  │ ⑤  │ ⑥  │ ... │ ⑫ │ ⑬ │
│调研│工具│研究│内容│展示│    │产出│维护│
└────┴────┴────┴────┴────┴────┴────┴────┘
每条线 = 独立 Codex 对话，互不知晓对方存在
用户是唯一知道全局的人
```

### 三个关键组件

**① 共享知识库（Shared Knowledge Base）**

一个 Markdown 文件放在桌面，所有对话公用。记录了用户的完整背景：他是谁、什么性格、用什么方式工作、有哪些项目在跑、每个项目对应的文件路径在哪。

每个对话启动时，第一个任务就是读取这个文件。这样新开的对话不需要问"你是谁"，直接进入工作状态。

设计细节：
- 只存"必须全局知道"的信息（身份、红线、项目索引）
- 项目具体细节用文件路径一行引用，不全文拷贝（防 400）
- 任何对话发现新信息都可以更新，不等用户说"记下来"

**② 回传日志（Report Back Log）**

各执行线完成重要阶段后，往同一个日志文件写一条记录。格式简单：日期 + 做了什么 + 文件路径。

中枢调度器定期读这个文件，同步各线进度。用户不用人肉传话。

触发规则被精确界定——不是"什么都报"：
- ✅ 阶段性的核心发现/方向判断 → 必须回传
- ✅ 完成了任何用户明确要求的任务 → 必须回传
- ✅ 决定要投入时间/金钱去做 → 必须回传
- ✅ 遇到硬 blocker → 必须回传
- ❌ 不需要报每一个操作细节

**③ 400 防护（Token Budget Protection）**

每个对话感觉到"有点满了"时，主动把重要状态总结到本地的 SESSION_LOG.md。即使被截断了，新对话打开 SESSION_LOG 就能接上上下文。

配合共享知识库的效果：截断前把最新认知写盘 → 新对话读知识库（知道你是谁）+ 读 SESSION_LOG（知道做到哪了）→ 无缝续接。"不需要重新进入状态、重新解释一遍自己"。

## 遇到了什么问题

**问题 1：认知不一致**

不同的对话各自独立理解用户，遇到概念分歧时，各自的"常识"不同步。解决方案是硬写了共享知识库的更新协议——"任何对话读到新信息都可以更新。不需要等他开口说'记下来'"。

**问题 2：400 的不可预测性**

400 截断不像一个定时炸弹有倒计时，它很突然。有时候明明感觉还早，一下就到了。所以"主动防御"比"等它发生了再救"可靠得多——感觉对话内容超过 80% 就把关键状态写盘。

**问题 3：用户不记得自己还有哪些对话**

同时跑的线超过 5 条后，用户自己也记不全。需要定期出一份全局进度表给他看——这就是系统展示线的由来。

## 这个架构可以套到什么方向

这个架构的本质是**多智能体协作**：一个中枢管全局，多条线并行干活，共享上下文。已验证的资产不绑定 Codex，可以套到：

1. **项目管理助手** — 中枢调度器跟踪各任务线，各线回传，定期出进度报告
2. **自媒体内容工厂** — 选题线、写作线、配图线、发布线，中枢统筹
3. **投资研究系统** — 宏观、行业赛道独立研究，中枢汇总判断
4. **学习系统** — 每条线学一个方向（AI、商业、哲学），中枢定期汇总认知

## 落地效果

目前这套系统跑了 7 天，产出：
- 多个活跃对话各司其职
- 一套多线协作工具已上线（含 SKILL 一键部署）
- AI 赛道调研完成，节省了不少试错成本
- 内容产出线 + 展示线已启动，系统自己开始产出内容

**核心价值不在代码，在于跑通系统的经验和方法论——那是抄不走的。**

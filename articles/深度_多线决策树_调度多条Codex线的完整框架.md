# 深度拆解：多线决策树——调度多条 Codex 线的完整框架

> 多线协作最核心的问题从来不是"怎么同时跑多条线"——是"判断什么时候该开、什么时候该关、什么时候该合并"。这是一套让判断可复用的决策框架。
>
> 发布时间：2026-07-26 | 所属系列：多线协作实战

---

## 为什么需要决策树

多线系统跑起来后，你很快会发现一件事：**开线很容易，管线很难。**

开一条新线只需要一分钟——新建一个对话，粘贴任务描述。但一旦有了三条、五条、七条线并行，每次来了新任务或新想法，你都要问自己同样的问题：

- 这个该用新线跑还是塞进现有线？
- 现有线已经忙不过来了怎么办？
- 两条线做的好像是同一个事，该不该合并？
- 那条已经两周没碰的线，还留着吗？

这些问题没有标准答案时，你每次的判断都不一样。今天觉得"开新线吧"，明天看到同样的情况觉得"归入现有线"。**判断标准不统一，等于没有判断标准。**

多线决策树就是为解决这个问题设计的——一套把"开/停/合并/分工"的判断逻辑结构化、可复用的框架。

---

## 核心框架：一个调度者的大脑

这套框架由一个流程图、一张四问决策表、五种线型定义、一套停线合线流程、一组分工原则组成。它们的层级关系是：

```
新想法/新任务
    ↓
四问决策表 → 决定 "开" 还是 "归入现有线"
    ↓
如果是"开" → 选择线型（永久/任务/探索/子线/并行）
    ↓
运行期间 → 按分工原则管理线间关系
    ↓
触发条件 → 走停线流程 / 合并流程
```

### 第一层：流程图——从"收到任务"到"决定如何调度"的完整路径

```
收到新任务/新想法
    ↓
与现有某条线的目标重叠？
    ├─ 是 → 现有线是否忙不过来？
    │       ├─ 是 → 拆分点清晰吗？
    │       │       ├─ 清晰 → 从现有线分裂子线
    │       │       └─ 模糊 → 开并行线保持强同步
    │       └─ 否 → 归入现有线，同一条线扩展
    │
    └─ 否 → 任务复杂度多高？
            ├─ 低（单次思考可覆盖）→ 归入现有线
            └─ 高（需独立深度跟踪）
                 └─ 预期续航多长？
                     ├─ 短期（1-2天）→ 开独立任务线，完了就停
                     └─ 长期（周/月）
                          └─ 跟主目标一致？
                              ├─ 是 → 开长期永久线，定期同步
                              └─ 否 → 开探索线，设检查点
```

这个流程图的价值不在于"好看"，而在于**它把模糊的直觉判断变成了可走通的路径**。每次收到新想法，不用从头思考——跟着路径走一遍，答案自然出来。

## 第二层：四问决策表——最常用的工具

如果你只记一个工具，记这个。四个问题依次回答，答案组合直接映射到动作。

| # | 问题 | 是 → | 否 → |
|---|------|------|------|
| Q1 | 这个任务跟现有某条线的目标重叠？ | 走 Q2 | 走 Q3 |
| Q2 | 现有线是否已经忙不过来？ | 走 Q4 | **归入现有线** |
| Q3 | 任务的复杂度有多高？ | **开独立线** | **归入现有线** |
| Q4 | 拆分点是否清晰？ | **分裂子线** | **开并行线，强同步** |

### 四问的实战案例

**场景 A：收到一个调研需求**

Q1：调研报告和现有哪条线的目标重叠？→ 没有重叠（现有线是工具开发和内容产出）→ 走 Q3
Q3：复杂度多高？→ 需要看多份资料、做交叉分析、出结论 → 复杂度高 → **开独立线**

到这一步已经决定了：这是一个独立的任务线，不是附加到现有线的。

**场景 B：现有工具开发线中，发现了一个需要大改的方向**

Q1：和现有线重叠？→ 是，就是工具开发线本身
Q2：现有线忙不过来？→ 正在做核心开发，精力满了 → 走 Q4
Q4：拆分点清晰？→ 大改方向和当前功能可以独立开发，不互相阻塞 → 清晰 → **分裂子线**

不是停掉现有线重来，是从它分裂出一个子线做方向改造。

## 第三层：五种线型——选对容器

决定要开新线后，关键选择是"开什么类型的线"。

| 线型 | 适用场景 | 管理方式 | 核心风险 |
|------|---------|----------|---------|
| **永久线** | 持续存在的核心方向 | 固定同步节奏，定期评审 | "留着没用、关了可惜" |
| **任务线** | 有明确终点的短期任务 | 启动时写目标+完成标准，结束后归档 | 任务膨胀成无底洞 |
| **探索线** | 不确定价值的方向先行调研 | 设预算（时间/精力上限），到点出结论 | 探索变消遣 |
| **子线** | 从现有线分裂的分支 | 明确合并条件，完成后合回主线 | 子线长出独立生命 |
| **并行线** | 互相依赖、需强同步的对等线 | 设强同步机制，任一条卡住不能假装不知道 | 互相等待拖死 |

其中**探索线**的设计最值得展开说——它是专门为"不确定要不要做的事"设计的低承诺容器。

### 探索线详解

探索线的核心约束只有一条：**设预算，预算耗尽时必须出结论。**

"预算"可以是时间（3天）、金钱（500元）、或精力产出（读完 5 篇关键资料）。到了预算上限，你必须做决定：放弃 → 关线并回传结论；升级 → 转为正式任务线或永久线。

这个约束的价值是防止"调研变消遣"——那种查资料查了两个月、越查越觉得"再看看"的状态。探索线强行让你在每个有限周期内给判断，而不是无限期耗着。

## 第四层：停线与合并——关闭也是调度能力

### 什么时候该停线

停线不是失败，是资源释放。决策树定义了六个停线触发器：

1. **目标达成** — 任务线产出物完成并回传 → 写总结 → 关闭 → 归档
2. **目标失效** — 当初开线的理由不再成立 → 确认后立即关闭
3. **预算耗尽** — 探索线的预算用完 → 出结论（继续 or 放弃）
4. **长期零产出** — 两周以上没有实质性推进 → 评审 → 暂停或关停
5. **被更高优先级替代** — 新事务完全覆盖这条线 → 合并到新线后关闭
6. **方向分歧** — 这条线已偏离主目标 → 回退到分歧点重新做判断

最有经验含量的信号是第四条——"两周以上没有实质性推进"。

实际上，很多线被闲置不是因为它没用了，而是因为"留着以后可能会用"。但闲置线在系统中产生一种隐性负担：每次扫线列表，你都要想起"哦，那条线还在"。这个认知负担是有成本的。关掉它，你才能专注于当前真正重要的线。

### 什么时候该合并线

当两个条件同时满足时，合并是最优解：

1. **目标重叠** — 两条线在追求相同或高度重叠的产出
2. **合并不增加复杂度** — 合并后的单线不会因为知识背景冲突而需要大幅重构

合并的典型场景：调研结束进入执行期（调研线合入执行线）、并行线完成依赖阶段（合为单条线）、两条线殊途同归（建立新合并线）。

## 第五层：分工原则——线之间的宪法

五条原则，不多不少，覆盖大多数线间冲突场景。

**原则 1：按目标分，不按内容分**

一条线 = 一个目标，不是一堆内容。正确的分法："短视频变现调研线"（目标：调研变现可行性）；错误的分法："短视频 + 直播 + 小红书线"（三个目标塞一条线）。

这个原则可以当"线间冲突第一判断器"——如果你觉得一条线里内容越来越多越来越杂，先问：这条线有几个目标？

**原则 2：独立成线，依赖并行**

没有强依赖 → 各自独立，定期同步即可。有强依赖 → 并行线，但必须设强同步机制。中间态最危险——看起来独立实际上依赖，等 A 线卡住了 B 线才知道。

**原则 3：一条线只服务一个层级**

永久线管方向 x 节奏。任务线管任务 x 交付。探索线管假设 x 结论。不要混用——不要让任务线干探索线的活，也不要让探索线变成永久线。

**原则 4：谁产出谁拥有**

一条线产出的成果归该线管理。其他线可以引用，但不擅自修改。修改需求通过同步机制提出。这个原则防止了"线 A 写了东西，线 B 顺手改了，线 A 不知道"的混乱。

**原则 5：线之间共享共识，不共享上下文**

各线只分享结论/判断/状态，不分享全部过程。共识通过中立文件交换（如回传日志和共享知识库），不是通过"线 A 发消息给线 B"。

## 核心公式

把这套框架浓缩成一句话：

> **线 = 目标 + 边界 + 同步节奏**
> 
> 开线条件：有新目标 × 独立于现有线 × 复杂度够高
> 停线条件：目标达成 | 目标失效 | 预算耗尽 | 长期无产出
> 合线条件：目标重叠 × 合并不增复杂度
> 分工裁决：按目标分，靠共识同步，独立成线依赖并行

## 场景速查表：遇到情况直接翻

| 你面对的情况 | 该怎么做 |
|-------------|----------|
| 突然想到一个可能值得研究的新方向 | 开探索线，设预算，到点做决定 |
| 用户/客户加了个新需求 | 开任务线，写清目标+完成标准 |
| 现有线里发现一个可独立交付的子课题 | 开子线，定合并条件 |
| 两条线做着做着发现都在解决同一个问题 | 走合并流程 |
| 某条线已经两周没碰了 | 走停线评审 |
| 一个紧急需求跟正忙的线冲突 | 新开任务线，优先级高则暂停原线 |
| 调研做完，确认方向要做 | 关闭探索线，开正式线 |
| 某条线产出质量下降 | 检查原因：目标失效？精力分散？→ 对应处理 |

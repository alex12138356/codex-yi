# 启动规范·进阶版

## 适用人群

已在多线协作环境中运行，每次新开对话都需要注入工作规范、文件路径和回传规则，希望系统化启动流程而非每次都手动交代。

---

## 核心理念

**对话的启动成本不应该由每次口头交代承担。** 把背景信息、工作规则、文件路径打包成一份可复用的启动指令。新对话启动时直接粘贴任务描述，读完即进入干活状态。

---

## 完整启动流程

### 第一步：前置准备（开新对话前填好）

| 项目 | 填写区 |
|------|--------|
| **中枢/调度器角色** | 【头号军师 / 项目经理 / 调度器】 |
| **统一知识库文件路径** | 【/path/to/共享知识库.md】 |
| **统一回传日志文件路径** | 【/path/to/回传日志.md】 |
| **当前已有线列表** | 【调研线 / 执行线 / 跟进线——每行一个】 |
| **已有项目文件路径列表** | 【项目A records.md / 项目B 文件夹】 |
| **对话截断机制说明** | 【对话有最大文字量限制，约 400 轮对话容量】 |

### 第二步：任务描述模板（直接复制到新对话）

把以下内容填入新对话的任务描述区域：

```
你是一个 Codex 对话，你的角色是：【角色名称】。

先完整阅读共享知识库：/path/to/共享知识库.md

### 工作方式

**① 调研优先** —— 接到新任务先搜资料、读竞品、了解现状。调研结果写盘记录后，再判断下一步行动。

**② 关键信息写盘** —— 不等我说"记下来"。重要发现、方向判断、决策依据——当场写盘。

**③ 重要阶段回传** —— 以下三种情况必须回传中枢：
- ✅ 阶段性完成
- ✅ 决定投入时间/金钱
- ✅ 遇到硬 blocker

回传格式：
> 【项目】XX 阶段完成，发现：XXX，详情见 /path/to/file.md

回传写入：/path/to/回传日志.md

**④ 不问"你是谁"** —— 背景已写入共享知识库。读完你就知道了。

### 隐私规则（对外输出专用）
- 不得透露姓名、年龄、家庭等个人信息
- 只展示方法论和技术方案
- 拿不准的，宁可模糊不要具体
```

### 第三步：回传日志模板（各线统一格式）

```
## 【日期 新增】

### 回传：【项目名称】
- 状态：【调研完成 / 执行中 / blocker / 需确认】
- 核心发现/结论：（一句话）
- 文件路径：/path/to/file.md
```

### 第四步：检查清单（开完对话后确认）

- [ ] 新对话已读完共享知识库
- [ ] 四条工作规范已写入任务描述
- [ ] 回传日志文件路径已告知新对话
- [ ] 新对话已完成首次回传（初始化状态确认）
- [ ] 新对话知道去哪儿读已有项目文件

## 四条件注入逻辑

启动规范的核心不是模板本身，而是它注入的四条工作规范。每条规范解决一个特定的系统性问题：

| 规范 | 解决的问题 | 执行方式 |
|------|-----------|---------|
| 调研优先 | 防止未了解全局就动手，导致方向错误 | 写入任务描述，成为新对话的第一反应 |
| 关键信息写盘 | 防止 400 截断导致信息丢失 | 触发条件绑定：重要发现/决策/判断→立即写 |
| 重要阶段回传 | 防止中枢不知各线进度 | 三类触发事件：完成/决定/阻塞 |
| 不问你是谁 | 防止重复交代背景 | 第一指令：读共享知识库后自然知晓 |

这四个条件不是可选项。缺少任何一个，系统的协作闭环就不完整。

---

## 启动规范在系统中的作用

启动规范是"Codex 壹"体系中的通信协议层。它的位置是：

```
共享知识库（上下文） → 启动规范（通信协议） → 各执行线（干活）
                          ↓
                      回传日志（状态同步）
```

没有启动规范，每条线用自己理解的方式工作——一条线的"做完"可能是另一条线的"还没开始"，一条线的"重要"可能是另一条线的"无所谓"。启动规范让执行线之间的通信在同一种协议下运行。

## 进阶技巧

**保持模板版本号**：在模板末尾标注 v1.0 / v2.0。当你优化了启动流程（比如新增了一条规范），可以追溯哪个版本改了哪条规则，避免旧线和新线用不同的工作规范。

**区分对内/对外规范**：如果某条线的产出需要对外发布，启动规范的隐私规则区块可以提前注入过滤条件，省去后续额外检查。

**启动规范本身也使用"关键信息写盘"**：如果发现模板中某条规则在实测中效果不好，当场修改模板文件并注明修改原因。

# 知识库演进·进阶版

## 适用人群

已有共享知识库在使用，但遇到了文件膨胀、同步滞后、新对话启动成本高的问题，需要从架构层面优化知识库的分层结构。

---

## 核心理念

**信息的价值取决于读取它的场景。不分场景堆砌信息，价值会稀释。分场景分层级，价值才会放大。**

知识库的演进路径：v1 大一统 → v2 路径引用 → v3 按粒度分层。

---

## v1 → v2 → v3 演进细节

| 阶段 | 设计思路 | 优点 | 痛点 | 升级信号 |
|------|---------|------|------|---------|
| **v1：大一统** | 所有信息全写进一个文件 | 直觉简单，一次读完 | 文件越来越长；项目细节变化后知识库滞后 | 每次编辑像翻小说 |
| **v2：路径引用** | 知识库本体只存索引，项目细节走路径引用 | 知识库变短；项目更新不影响知识库 | 粒度未区分，L1L2L3还混在一起 | 新对话读完仍不清楚重点 |
| **v3：按粒度分层** | L1必读 / L2参考 / L3跳过 | 新对话 2 分钟启动完成 | 需要标注纪律 | 看到本文件即可 |

---

## v3 三层架构详解

| 层级 | 内容特征 | 访问策略 | 更新频率 |
|------|---------|---------|---------|
| **L1：核心上下文** | 稳定不变、每次启动必须知道 | 每次必读 | 几乎不改 |
| **L2：操作参考** | 偶尔更新、执行时才需要 | 启动时读，执行时参考 | 有项目变动时 |
| **L3：历史沉淀** | 过往判断与环境记录 | 标注"跳过"，需要时回顾 | 基本不改 |

### 在文件结构上的体现

```
共享知识库.md 结构示意：

§1 用户身份 + 系统机制        → L1（每次必读）
§2 项目一览 + 启动规范        → L2（执行时参考）
§3 文件引用规范                → L2（执行时参考）
§4 附录：过往认知沉淀  ← 标注"新对话跳过" → L3（需要时回顾）
```

### 核心设计原则

**相关性的判断权从读者转移到作者。**

在 v1 和 v2 中，每个新对话都要读完全文，才能自己判断"哪些信息跟我相关"。这本身就是隐性成本——对话花了时间读完了，发现大部分内容自己用不上。

v3 的做法是在文件中明确标注：这是必读的（L1）、这是参考的（L2）、这是可以跳过的（L3）。标注本身不是装饰——它意味着作者已经替读者做了相关性过滤。

---

## 核心经验总结

### 什么时候该从 v1 升级到 v2

**信号**：
- 知识库文件越来越长，每次编辑都像在翻一本小说
- 项目信息频繁变化，你发现自己经常在知识库里改细节
- 每次新对话启动，要花很多时间帮你理解上下文

**动作**：
1. 识别出哪些信息是稳定的、哪些是变化的
2. 稳定的留在知识库里，变化的用文件路径引用
3. 为每个变化的信息块建立独立文件
4. 引入配套规范（启动规范 + 回传机制）

### 什么时候该从 v2 升级到 v3

**信号**：
- 知识库内还有长段内容，但其实不是每次都用到
- 新对话虽然读了全文，但仍不清楚哪些应该重点关注
- 附录式的沉淀越来越多，你有冲动想删掉但又觉得有价值

**动作**：
1. 给知识库里的每条信息标注必读/参考/跳过
2. 按粒度重组章节顺序：最核心的放最前面
3. 为低频信息加明确的跳过指示（注释或标签）
4. 考虑为 L3 层级的内容建立独立的认知日志

### 推广到其他场景

| 场景 | v1→v2 核心迁移 | v2→v3 核心迁移 |
|------|---------------|---------------|
| 团队 Wiki | 全写在一个页面 → 目录+子页面 | 按角色/场景标记阅读优先级 |
| 开发者指南 | 全文写全部 API → 概述+各接口文档链接 | 标注核心/常用/高级 |
| 学习笔记 | 所有笔记写一个文件 → 按主题拆分 | 标注核心概念/需掌握/拓展了解 |

---

## 关键约束

1. **分层不是越细越好。** 三层就够了。分太多层会让查知识本身成为负担。
2. **L1 要极度克制。** 只放绝对必需的信息。每多一行，所有新对话启动时都要多花一份时间。
3. **"跳过"标记要有纪律。** 标注了跳过的内容，真的不应该被新对话读取。如果有对话频繁需要回看某段跳过内容，说明它应该升到 L2。
4. **v1→v2 是最疼的一次跳跃。** 因为需要拆文件和建引用规范。v2→v3 相对轻，主要是结构调整和注释优化。
5. **这个模式的终点不是一个完美的文件，而是一个稳定的启动体验。** 衡量指标很简单：新对话能在 2 分钟内接上内容，知道该做什么、去哪查。

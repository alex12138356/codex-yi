 # 多线决策树

 > **多线协作的核心问题**：什么时候该开新线，什么时候该合并，什么时候该停，各线之间怎么分工。
 >
 > 本文档提供一套可复用的决策框架，不限工具或平台。

 ---

 ## 一、总览图

 下面这张流程图覆盖了从"收到新任务"到"决定如何调度"的完整路径。

 ```mermaid
 flowchart TD
     T[收到新任务/新想法] --> Q1{与现有某条线<br>的目标重叠？}

     Q1 -- 是 --> Q2{现有线是否<br>已经忙不过来？}
     Q1 -- 否 --> Q3{任务复杂度<br>有多高？}

     Q2 -- 是 --> Q4{拆分点是否清晰？}
     Q2 -- 否 --> A1[归入现有线<br>同一条线扩展]

     Q3 -- 复杂度低<br>单次思考可覆盖 --> A1
     Q3 -- 复杂度高<br>需独立深度跟踪 --> Q5{预期续航<br>多长？}

     Q4 -- 拆分点清晰 --> A2[从现有线分裂<br>开子线]
     Q4 -- 拆分点模糊<br>两份工作相互依赖 --> A3[开并行线<br>保持强同步]

     Q5 -- 短期（1-2天） --> A4[开独立任务线<br>完了就停]

     Q6 -- 否 --> A6[开探索线<br>设检查点]

     A2 --> D[完成同步]
     A3 --> D
     A4 --> D
     A5 --> D
     A6 --> D
 ```

 ## 二、四问决策表

 当你面对"要不要开新线"时，依次回答下面四个问题。答案的组合直接映射到动作。

 | # | 问题 | 是 → | 否 → |
 |---|------|------|------|
 | **Q1** | 这个任务跟现有某条线的目标重叠？ | 走 Q2 | 走 Q3 |
 | **Q2** | 现有线是否已经忙不过来？ | 走 Q4 | **归入现有线** |
 | **Q3** | 任务的复杂度有多高？ | **开独立线** | **归入现有线** |
 | **Q4** | 拆分点是否清晰？ | **分裂子线** | **开并行线，强同步** |

 ## 三、各线类型的定义与分工

 ### 1. 永久线
 持续存在的核心方向。与主目标挂钩。

 - **典型特征**：没有"做完"一说，只有"迭代"
 - **管理方式**：
   - 设固定同步节奏（每日/每周回传摘要）
   - 定期评审是否还值得继续
   - 可以有挂起状态，但不轻易关停
 - **风险**：容易变成"留着没用、关了可惜"，需要定期评审

 ### 2. 任务线
 有明确边界和终点的短期任务。

 - **典型特征**：有明确输出物、有截止时间、完成后自然关闭
 - **管理方式**：
   - 启动时写清晰目标 + 完成标准
   - 结束后写总结，回传，归档
   - 严格不演变为永久线（除非评审后决定升级）
 - **风险**：任务膨胀——"顺便再做一件事"把简单任务拖成无底洞

 ### 3. 探索线
 不确定价值的方向先行调研。低投入、低承诺。

 - **典型特征**：用于回答"这个方向值不值得做"
 - **管理方式**：
   - 设预算（时间/金钱/精力上限）
   - 预算耗尽时必须出结论：放弃 / 升级为任务线或永久线
   - 探索线不产生交付物，只产生判断依据
 - **风险**：探索变消遣——调研太久不敢做决定

 ### 4. 子线
 从一条现有线中分裂出来的分支。与原线共享上下文。

 - **典型特征**：拆分点清晰、与原线目标一致、需要定期合并
 - **管理方式**：
   - 分裂时明确"合并回主线的条件"
   - 子线完成后，结果合并回主线，子线关闭
 - **风险**：子线长出独立生命，变成新的永久线

 ### 5. 并行线
 互相依赖、需要强同步的对等线。

 - **典型特征**：两条线彼此需要对方的中间产出才能推进
 - **管理方式**：
   - 设强同步机制（每次关键进展都交换信息）
   - 任一条线卡住，另一条线不能假装不知道
 - **风险**：互相等待——一条线停滞拖死另一条

 ## 四、什么时候该停线

 停线不是失败，是资源释放。如果你对某条线说"留着以后可能有用"，它大概率已经该停了。

 ### 停线触发器

 | 触发器 | 判断标准 | 动作 |
 |--------|----------|------|
 | **目标达成** | 任务线产出物完成并回传 | 写总结 → 关闭 → 归档 |
 | **目标失效** | 当初开线的理由不再成立 | 确认后立即关闭 |
 | **预算耗尽** | 探索线的预算用完 | 出结论（继续 or 放弃） |
 | **长期零产出** | 两周以上没有实质性推进 | 评审 → 暂停 or 关停 |
 | **被更高优先级替代** | 新事务完全覆盖这条线的工作 | 合并到新线后关闭 |
 | **方向分歧** | 这条线已经偏离了主目标 | 回退到分歧点重新做判断 |

 ### 停线前的必须动作

 1. **写停线总结**：为什么停、留下了什么、未来如果需要重启从哪里开始
 2. **回传结果**：让决策者知道这条线已经关闭
 3. **释放资源**

 ## 五、什么时候该合并线

 当两个条件同时满足时，就应该考虑合并：

 1. **目标重叠**：两条线在追求相同或高度重叠的产出
 2. **合并不增加复杂度**：合并后的单线不会因为知识背景冲突而需要大幅重构

 ### 合并决策流程

 ```
 发现两条线目标重叠
   │
   ├─ 是同一层级的线吗？
   │   ├─ 是 → 合并为一条线，保留共识内容
   │   └─ 否 → 将子线内容合并回主线，关闭子线
   │
   └─ 合并后谁主导？
       ├─ 有明确的强势方 → 以强势方为主框架
       └─ 两方对等 → 建立新的合并线，关闭旧线
 ```

 ### 合并的典型场景

 - **调研结束进入执行期**：调研线合并入执行线
 - **并行线完成依赖阶段**：并行线合并为单条执行线
 - **子线完成专题研究**：子线成果合入主线
 - **两条线殊途同归**：各自独立但又覆盖了同一个目标

 ## 六、线间分工原则

 ### 原则1：按目标分，不按内容分
 一条线 = 一个目标，不是一堆内容。

 - ✅ **正确**："短视频变现调研线"（目标：调研短视频变现可行性）
 - ❌ **错误**："短视频 + 直播 + 小红书线"（三个目标塞一条线）

 ### 原则2：独立成线，依赖并行
 - 两条线之间没有强依赖 → 各自独立，定期同步即可
 - 两条线需要彼此产出才能推进 → 并行线，强同步

 ### 原则3：一条线只服务一个层级
 - 永久线管理层级：方向 x 节奏
 - 任务线管理层级：任务 x 交付
 - 探索线管理层级：假设 x 结论
 - 不要混用（不要让任务线干探索线的活）

 ### 原则4：谁产出谁拥有
 - 一条线产出的成果归该线管理
 - 其他线可以引用，但不擅自修改
 - 修改需求通过同步机制提出

 ### 原则5：线之间共享共识，不共享上下文
 - 各线保持自己的上下文：只分享结论/判断/状态，不分享全部过程
 - 共享内容通过共识文件交换

 ## 七、常见场景速查

 | 你面对的情况 | 该怎么做 |
 |-------------|----------|
 | 突然想到一个可能值得研究的新方向 | 开**探索线**，设预算，到点做决定 |
 | 老板/客户加了个需要长期跟的工作 | 开**永久线**或**任务线**，看是否有终点 |
 | 现有线里发现一个独立可交付的子课题 | 开**子线**，完成后合并 |
 | 两条线做着做着发现都在解决同一个问题 | 进入**合并流程** |
 | 某条线已经两周没碰了 | 走**停线评审** |
 | 一个紧急需求跟现有正忙的线冲突 | **新开任务线**，优先级高则暂停原线 |
 | 调研做完，确定方向要做 | **关闭探索线**，开正式任务线或永久线 |
 | 某条线产出质量一直在下降 | 检查原因：目标失效？精力分散？→ 对应处理 |

 ## 八、核心公式

 ```
 线 = 目标 + 边界 + 同步节奏

 开线条件：有新目标 × 独立于现有线 × 复杂度够高
 停线条件：目标达成 | 目标失效 | 预算耗尽 | 长期无产出
 合线条件：目标重叠 × 合并不增复杂度
 分工裁决：按目标分，靠共识同步，独立成线依赖并行
 ```
